- **2026-05-13**: Fixed the **"blank PDF after download"** bug in [lib/screens/pdf_view_screen.dart](lib/screens/pdf_view_screen.dart). Root cause: the downloader used `package:http` `Client.send(Request)` whose streamed response surfaces *raw* bytes — when the GitHub raw → CDN chain returned `Content-Encoding: gzip`, the file written to disk was the gzip-compressed PDF, so `SfPdfViewer.file` rendered a blank page (no error, no exception — the file existed and was non-empty so `_resolve()` happily transitioned to `ready` on the next open too). Fix: rewrote the download path to `dart:io HttpClient` (`getUrl` + `followRedirects: true, maxRedirects: 8`), which auto-decompresses gzip and natively follows the redirect chain. Added a `%PDF` magic-byte check on the staged `.part` file before the atomic rename — if the leading 4 bytes aren't `0x25 0x50 0x44 0x46` (e.g., GitHub served an HTML 404 page, login wall, or LFS pointer), the new `_NotAPdfException` is thrown and surfaced via a localized `downloadInvalidPdf` ARB string so the user sees an actionable message instead of an Exception toString. `package:http` dropped from `pubspec.yaml` (no other callers). Files modified: [lib/screens/pdf_view_screen.dart](lib/screens/pdf_view_screen.dart), [pubspec.yaml](pubspec.yaml), [lib/l10n/app_en.arb](lib/l10n/app_en.arb) (+ generated l10n).
